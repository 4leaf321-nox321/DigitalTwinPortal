# 제조 모니터링 — 부문 설계안

> 검토 중. 이 문서는 **결정이 아니라 검토안**이다 — 제조 담당 확인 전에는 코드로 옮기지 않는다.
> 상위 문서: [PLAN.md](./PLAN.md) 3절(엔진) · 9절 H 판. 형제 문서: [PLAN-automation.md](./PLAN-automation.md).
> **전기·전자 제품 제조**를 전제로 적었다 — SMT·조립·검사가 중심이고, 설비가 대개 스스로
> 자료를 내놓는 편이라 「수집」보다 **「판단·대응」에서 갈린다**(3-2).
> 2026-08-29 작성.

---

## 0. 이 문서가 답하는 것

「제조 모니터링」을 성숙도 모듈의 부문으로 세울 때

1. **무엇을 대상으로 매기나** — 설비 개체인가, 공정인가, 관측 항목인가
   (사업부마다 라인·설비가 다른데 그걸 다 세울 수 있나)
2. **상태 · C/T · 알람을 어떻게 담나** — 이 셋으로 집계하는 자리가 이미 있다
3. **사업부마다 제조 조직이 따로 있는 것**이 판·권한에 어떻게 들어오나
4. 시뮬레이션의 자동화 축 · 디지털 스레드의 데이터 확보 축과 **겹치지 않나**

---

## 1. 자리

성숙도 모듈의 **다섯째 부문**(검토안). 앞의 넷과 같은 엔진을 쓴다 —
「대상 × 수단 = 연계, 연계마다 축별 칸 + 근거 + 이력」.

**채우기는 사업부 기준이다.** 사업부마다 제조 조직이 따로 있으므로 지금 권한
체계(자기 사업부만 평가, 사무국·관리자는 전 사업부)가 그대로 맞는다 — 조직
문제로 걸릴 것이 없다. 화면의 줌 세 단(전사 → 사업부 → 연계)도 그대로다.

**「제조 디지털 트윈 과제 관리」 모듈과는 무관하다.** 읽지도 쓰지도 않는다.
저쪽은 **하는 일**(과제)을 관리하고 여기는 **지금 어디까지 왔나**(상태)를 잰다 —
로드맵 정보 모듈과 시뮬레이션 부문이 갈라 선 것과 같은 자리다.

## 2. 대상과 수단 — 개체가 아니라 **공정 단계**

### 2-1. 시뮬레이션 부문과 맞춰 읽기

| | 시뮬레이션 | 제조 모니터링 |
|---|---|---|
| **대상** | 시험 **항목**(낙하 시험) — 「1회 시험」이 아니다 | 라인의 **공정 단계**(A라인 · SMT 실장) — 「마운터 3호」가 아니다 |
| **수단** | 시뮬레이션(낙하 구조 해석) | 수집·감시 수단(설비 인터페이스 · SPC · 이상탐지 모델) |
| **연계** | 시험 × 시뮬레이션 | 공정 × 수집 수단 |

시뮬레이션의 대상은 **종류 수준**이다. 낙하 시험을 몇 번 하든 줄은 하나이고,
해석 모델이 바뀌어도 「낙하 시험」은 남는다. 제조도 같은 높이로 잡아야 한다.

⚠️ **설비 개체를 대상으로 두면 안 된다.** 사업부마다 라인·설비가 다르고 대수가
수백이라 목록이 폭발하고, 설비를 교체·증설할 때마다 줄과 이력이 사라진다.
시뮬레이션에서 「낙하 시험 1회」를 대상으로 두지 않은 것과 같은 이유다.

### 2-2. 계층 — 어디까지 줄로 세우나

```
사업부                          ← 판·권한의 단위 (그대로)
 └ 사업장 · 라인                 ← 대상의 속성 (묶음·필터)
    └ 공정 단계                  ← ★ 대상(subject) 한 줄
       └ 설비군(같은 기종·역할)    ← 근거의 「n/N 대」
          └ 설비 개체             ← 세지 않는다
```

| | 대상 | 왜 |
|---|---|---|
| **세운다** | **라인 × 공정 단계** — 「A라인 · SMT 실장」, 「B라인 · 최종 조립」 | 라인이 달라 수준이 다르면 줄이 갈리고, 공정 이름은 전사 어휘라 사업부끼리 비교된다 |
| **안 센다** | 마운터 8대·리플로우 2대 | 같은 공정의 설비 사이 차이는 **근거의 비율**로 — 「상태 수집 8/12대」 |

**설비 사이 차이는 비율로 받는다.** 디지털 스레드의 「데이터 확보」 축에서 확보
비율 %를 근거로 받은 것과 같은 장치다. 「12대 중 8대만 상태가 잡힌다」는 축을
흐리지 않고 근거에 남고, 화면이 그 비율을 같이 보여 준다.

혼자 다른 기종이라 정말 갈라야 하는 설비는 **그 공정 아래에 설비군을 한 줄 더
세우는 것도 허용**한다 — 한 시험에 시뮬레이션을 여럿 다는 것과 같은 자유도다.
다만 **기본은 공정**이고, 화면의 안내 문구도 그렇게 말한다.

### 2-3. 규모 — 셀 수 있는 크기인가

| | 개체를 세우면 | 공정으로 세우면 |
|---|---|---|
| 사업부 하나 | 설비 200~800 | 라인 4~6 × 공정 5~8 ≒ **20~50 줄** |
| 전사 다섯 | 1,000~4,000 | **100~250 줄** |

시뮬레이션 부문이 시험 44 · 연계 50으로 도는 것과 같은 크기다. 처음에는 **주요
라인 한둘**만 세우고 넓힌다(6절).

### 2-4. 공정 단계는 전사 표준 어휘 — 전기·전자 제조 기준

라인·설비 이름은 사업부마다 다르지만 **공정은 대체로 같은 말을 쓴다.** 표준
어휘를 코드가 주고 사업부가 골라 세운다 — 디지털 스레드의 「표준 구간 → 구간」과
같은 구조다.

| 갈래 | 표준 공정 (초안) |
|---|---|
| **PCBA** | 솔더 인쇄 · SMT 실장 · 리플로우 · SPI·AOI 검사 · 수삽·후공정 · 코팅·세척 |
| **기구 부품** | 사출 · 프레스·판금 · 도장·증착 · 후가공 |
| **조립·검사** | 모듈 조립 · 최종 조립 · 기능 검사(ICT·FCT) · 캘리브레이션 · 외관 검사 |
| **그 밖** | 자재 입고 검사(IQC) · 신뢰성 시험 · 포장 · 물류 · 유틸리티(공조·용수·전력) |

- 없는 공정은 직접 적는다. 자주 적히는 이름은 사무국이 표준으로 올린다.
- **이 어휘가 사업부 간 비교의 뼈대다.** 라인 이름이 「A라인」·「1호기 라인」으로
  갈려도 「SMT 실장」끼리는 나란히 선다.
- 전자 제조라 **SMT 갈래가 가장 촘촘하다.** 설비가 스스로 자료를 내놓는 자리라
  성숙도가 가장 앞서 있고, 뒤처진 자리(사출·조립·포장)와의 격차가 이 부문에서
  가장 먼저 눈에 띌 그림이다.

### 2-5. 대상의 속성

| 속성 | 값 | 왜 |
|---|---|---|
| **공정 단계** | 표준 어휘(2-4) + 직접 적기 | 사업부 간 비교의 기준 |
| **라인·사업장** | 자유 입력(사업부의 어휘) | 모판 묶음·필터의 기준 |
| **담당 조직** | 제조기술 / 제조 / 품질 … (포탈 부서) | 사업부마다 제조 조직이 따로 있다 — 시뮬레이션의 「담당 부서」 칸을 그대로 쓴다 |
| **설비 대수** | n대(근거) | 축이 아니라 규모의 눈금. 「8/12대」의 분모 |

### 2-6. 한 공정에 수단이 여럿

시뮬레이션에서 한 시험에 시뮬레이션이 여럿 걸리듯, 한 공정에 수집 수단이 여럿
걸린다. **평가는 연계마다** 붙으므로 수단별로 수준이 갈려 보인다:

| 연계 | 무엇이 켜지나 |
|---|---|
| A라인 SMT 실장 × **설비 인터페이스** | 기본 계측: 상태 · C/T · 알람 / 수집 방식: 실시간 자동 수집 |
| A라인 SMT 실장 × **SPI·AOI 수집** | 기본 계측: 품질 / 판단 수준: 이상 판정 |
| A라인 리플로우 × **온도 프로파일 수집** | 기본 계측: 공정 변수 / 판단 수준: 예측 |

공정 단위 수치는 **그 공정에 걸린 연계들을 합쳐서** 나온다 — 시뮬레이션의
「항목 정확도 = 연결된 시뮬레이션 값의 집계」와 같은 구조다.

## 3. 축

### 3-1. 기본 계측 (묶음 — 겹쳐 켠다) ⭐

**무엇을 잡고 있나.** 이 부문의 뼈대다.

| 칸 | 뜻 |
|---|---|
| **상태** | 가동·정지·대기·비가동 사유가 시간축으로 남는가 |
| **C/T** | 사이클 타임이 사이클마다(또는 주기로) 남는가 |
| **알람** | 설비 경보가 코드·시각과 함께 남는가 |
| **품질** | 불량·수율이 그 공정 단위로 남는가(SPI·AOI·ICT·FCT 판정 포함) |
| **공정 변수** | 리플로우 온도 프로파일·인쇄 압력·성형압 같은 공정 조건이 남는가 |

- 근거: 수집 주기(초·분) · 보존 기간 · 월 알람 건수 · 가동률 % · **적용 설비 n/N 대**를
  적는다. 숫자는 그 공정의 실제 값이다. 숫자는 근거일 뿐 축이 아니다 — **실시간 연동은 하지
  않는다**(PLAN.md 10절 「KPI 를 읽거나 쓰지 않는다」와 같은 선).
- 대표 수치: **항목별 채택률 띠 + 적용 단계 수(평균)**. 시뮬레이션의 자동화 축과
  같은 화면 문법이라 요약·상세·모판이 그대로 돈다.

### 3-2. 나머지 축

| 축 | 종류 | 칸 | 근거 | 대표 수치 |
|---|---|---|---|---|
| **수집 방식** | 택1 | 수기·일지 → 사람이 취합해 올림 → 설비에서 주기 수집 → 실시간 자동 수집 | 수집 주기, 대상 설비 n/전체 | 「주기 수집」 이상 % |
| **판단 수준** | 택1 | 사람이 본다 → 이상 판정(기준선·관리도) → 원인 진단 → 예측(고장·불량 예지) → 자동 보정 | 판정 규칙의 근거 | 「이상 판정」 이상 % |
| **대응 연결** | 택1 | 알림 없음 → 사람에게 알림 → 담당·조치 표준이 붙은 알림 → 시스템이 조치(정지·보정) → 조치 결과가 다시 학습으로(폐루프) | 평균 대응 시간 | 「조치 표준」 이상 % |
| **적용 범위** | 택1 | 시범 1~2대 → 일부 설비 → 그 공정 전 설비 → 새 설비에도 기본 적용(표준) | 적용 설비 n/N 대 | 「그 공정 전 설비」 이상 % |
| **신뢰도** | **값**(%) | 미평가 → 70% 미만 → 70~90% → 90% 이상 (사업부별 문턱) | 유효 데이터율 또는 알람 유효율(오경보 제외) | 평균 % |

**왜 판단 수준과 대응 연결을 갈랐나.** 제조에서 가장 흔한 모습이
「데이터는 다 모으는데 아무도 안 본다」와 「예측까지 하는데 알림이 주인 없는
대시보드에만 뜬다」다. 하나로 합치면 뒤엣것이 「예측 단계」로 좋게 읽힌다.
**갈라 두면 그 함정이 표에 그대로 드러난다** — 이 부문의 값어치가 거기 있다.

**신뢰도가 값(%)인 이유.** 정확도 축과 같은 구조를 그대로 쓴다(값→칸, 사업부별
문턱, 기록 누적). 오경보가 잦은 알람은 곧 아무도 안 보게 되므로, 판단 수준이
높아도 신뢰도가 낮으면 실제로는 안 쓰인다는 것이 한 표에서 보여야 한다.

### 3-3. 상태 · C/T · 알람 기준 집계는 이렇게 나온다

세 항목으로 집계하는 자리가 이미 있으므로 **화면에서 그 셋을 앞에 세운다.**

- **전사 요약**의 「기본 계측」 칸: 항목별 채택률 띠 다섯 중 앞의 셋(상태·C/T·알람)이
  먼저 오고, 그 셋만으로 한 줄을 읽을 수 있다 — 「MX 상태 92% · C/T 78% · 알람 64%」.
- **필터**: 「상태만」 「C/T만」 「알람만」으로 좁히면 그 항목을 켠 공정만 남는다.
- **모판**: 색의 기준을 「기본 계측」으로 두면 켠 개수가 색이 되고, 라인으로 묶으면
  **라인별로 어디가 비었는지**가 한눈에 보인다.
- **변화**: 축마다 선 그래프이므로 「알람 수집이 지난 분기에 몇 % 올라갔나」가 그대로 나온다.

세 항목이 특별해서 축을 따로 만드는 것이 아니라, **한 축의 앞 세 칸으로 두고
화면이 그 셋을 먼저 읽게** 한다. 항목이 늘어도 표가 안 바뀐다.

## 4. 겹치지 않는다 — 경계

| 무엇 | 무엇을 재나 | 대상 |
|---|---|---|
| 시뮬레이션의 **자동화 축** | 해석 파이프라인이 도는 정도 | 시험 × 시뮬레이션 |
| 설계 자동화 | 설계 산출물이 나오는 과정 | 설계 업무 × 자동화 수단 |
| 검증 자동화 | 규칙 판정이 도는 과정 | 검증 항목 × 검증 수단 |
| 디지털 스레드의 **데이터 확보 축** | 데이터가 **조직·시스템을 건너는 자리**에서 어떻게 잡히나 | 구간 |
| **제조 모니터링의 수집 방식 축** | **현장에서 관측이 잡히는 정도** | 라인 × 공정 × 수집 수단 |

스레드와의 경계를 한 줄로: **스레드는 전달, 모니터링은 관측.**
같은 제조 데이터레이크가 양쪽에 이름을 올려도 된다 — 스레드에서는 「제조 →
개발로 수율이 어떻게 건너가나」를, 모니터링에서는 「그 공정의 값이 애초에
잡히나」를 잰다.

⚠️ 화면 문구에는 늘 대상을 붙여 부른다. 「수집」·「자동화」 같은 말이 여러 부문에
있어서, 안 적으면 반드시 헷갈린다.

## 5. 화면 — 새로 만들 것이 없다

| 화면 | 그대로 도나 | 손볼 곳 |
|---|---|---|
| 요약(전사) | ✅ 축 × 사업부 | 축마다 대표 수치 함수만 추가(3절 오른쪽 열) |
| 요약(사업부) | ✅ 축마다 판 | — |
| 상세 | ✅ 한 줄에 수단 하나, 켠 것 배지 | 열 이름(시험 → 공정) |
| 변화 | ✅ 축마다 선 그래프 | — |
| 모판 | ✅ 담당 부서로 묶고 축 색 | **묶음을 「라인」·「공정」으로도** 고를 수 있게 |
| 목록 | ✅ 대상 × 수단 표 | 「라인」·「공정」 열 + 필터, 설비 대수는 작은 글씨 |
| 연계 창 | ✅ 축별 척도·근거·이력 | — |

축 종류가 전부 이미 있는 것(택1 rung · 값 value · 묶음 set)이라 새 화면이 없다.
새 부문이 화면을 새로 요구하면 **엔진 설계가 틀린 것**이다(PLAN.md 9절 H 판).

## 6. 채우기

**공정은 표준 어휘에서 고르고, 라인·설비 이름은 사업부가 적는다**(2-4).

```
코드가 주는 것                          사업부가 채우는 것
표준 공정 18(전기·전자 제조)              라인·사업장 이름, 담당 조직, 설비 대수
기본 계측 5(상태·C/T·알람·품질·공정 변수)   → 공정을 고르고 라인을 적으면 한 줄이 선다
```

- 처음 채우기는 **주요 라인 한둘**로 시작한다. 라인을 다 세우려 들면 시작을 못 한다.
  라인 하나면 공정 5~8줄이라 반나절이면 채운다. **SMT 라인 하나**가 첫 시범으로
  가장 좋다 — 설비가 자료를 내놓고 있어 축이 곧바로 채워지고, 나머지 공정의 기준선이 된다.
- 사업부가 직접 적은 공정 이름이 모이면 사무국이 표준으로 올린다(시스템 사전의
  「합치기」와 같은 자리).
- **설비 대수는 근거 칸**이다. 대수가 늘어도 줄이 안 늘고, 설비를 바꿔도 이력이 남는다.

## 7. 데이터 모델 영향

| 무엇 | 크기 |
|---|---|
| `definitions.py` 에 부문 추가 + 축 여섯 정의 | 설정 추가만 — 코드 안 갈림 |
| `subject.line`(라인·사업장) · `subject.process`(공정 단계, 표준 어휘) | 마이그레이션 1개(컬럼 둘). `subject.domain`(자동화 부문의 분야)과 같은 자리에 함께 넣으면 마이그레이션 하나로 끝난다 |
| 표준 공정 어휘 | `definitions.py` 의 목록 하나 — 표가 아니다(디지털 스레드의 데이터 종류와 같은 결) |
| 담당 조직 | 기존 `agent.department_id`(포탈 부서) 재사용 — 새 칸 없음 |
| 신뢰도의 사업부별 문턱 | 기존 설정 구조(정확도 문턱)와 같은 자리 |

씨앗·샘플 뷰는 기존 스크립트에 부문 하나를 더하는 것으로 끝난다.

## 8. 남은 결정

| 결정 | 갈래 | 지금 생각 |
|---|---|---|
| 대상의 알갱이 | 설비 개체 / 설비군 / **라인 × 공정** | **라인 × 공정**(2-2). 개체는 목록이 폭발하고 교체 때 이력이 사라진다. 혼자 다른 기종은 그 아래 설비군을 한 줄 더 |
| 표준 공정 어휘 | 코드가 준다 / 사업부가 적는다 | **코드가 주고 골라 쓴다**(2-4). 라인 이름은 갈려도 공정끼리는 비교돼야 한다 |
| 같은 공정인데 설비마다 다를 때 | 줄을 가른다 / 비율로 받는다 | **비율로**(「상태 8/12대」). 가르기 시작하면 설비 개체로 돌아간다 |
| 신뢰도의 뜻 | 유효 데이터율 / 알람 유효율 | 둘 다 받아 보고 하나로 좁힌다. 사업부가 어느 쪽을 셀 수 있는지가 답 |
| 라인 목록 | 자유 입력 / 사업부 설정에 등록 | 자유 입력으로 시작, 이름이 갈리기 시작하면 설정으로 올린다 |
| 품질·공정 변수 | 기본 계측에 넣나 | 넣되 **뒤에 둔다.** 상태·C/T·알람이 앞 세 칸(3-3) |
| 사업장이 여럿인 사업부 | 라인 속성으로 / 사업부를 쪼개서 | **라인 속성으로.** 사업부를 쪼개면 다른 모듈의 사업부 목록과 어긋난다 |
| 부문 이름 | 「제조 모니터링」 / 「설비 모니터링」 | 「제조 모니터링」 — 설비만이 아니라 공정·품질도 담는다 |
