# 설계 자동화 · 검증 자동화 — 부문 설계안 (안 B)

> 검토 중. 이 문서는 **결정이 아니라 검토안**이다 — 사업부 확인 전에는 코드로 옮기지 않는다.
> 상위 문서: [PLAN.md](./PLAN.md) 3절(엔진) · 3-1절(이 두 부문의 자리) · 9절 H 판.
> 2026-08-29 작성.

## 0. 이 문서가 답하는 것

「설계 자동화」와 「검증 자동화」를 성숙도 모듈의 부문으로 세울 때

1. **무엇을 대상으로 매기나** — 시뮬레이션의 「시험 항목 × 시뮬레이션」에 해당하는 것이 무엇인가
2. **축이 모자라지 않나** — 자료를 보면 물어볼 것이 「돌아가는가」 하나뿐인 듯한데, 그것으로 화면이 서는가
3. **기구·회로를 어떻게 가르나** — 부문을 더 쪼갤 것인가, 속성으로 둘 것인가
4. **시뮬레이션의 「자동화」 축과 겹치지 않나**

## 1. 왜 부문을 둘로 두나 (안 A 대신 안 B)

한 부문(「설계·검증 자동화」)으로 합치는 안 A도 검토했다. 축이 거의 같아
합치면 요약표에서 나란히 비교되고 화면이 하나로 준다는 것이 장점이었다.

**둘로 두기로 한 근거**

| 갈래 | 설계 자동화 | 검증 자동화 |
|---|---|---|
| 일의 성격 | **만든다** — 없던 산출물을 낸다 | **판정한다** — 있는 것이 규칙에 맞는지 본다 |
| 잘 됐다의 뜻 | 산출물이 어디까지 자동으로 나오나 | 규칙 중 얼마나 자동으로 걸러지나 · 언제 걸리나 |
| 틀렸을 때의 값 | 사람이 고쳐 쓴다(손해는 시간) | **놓치면 불량이 나간다**(손해는 품질) |
| 재는 단위 | 업무 1건의 소요 시간 | 규칙 커버리지 · 개입 시점 |

「잘 됐다」의 뜻이 다르면 대표 수치가 달라야 하고, 대표 수치가 다르면 한 표에
섞을 때 열 하나가 늘 비어 보인다. 합치면 축 아홉 중 넷이 「이 종류에는 해당
없음」이 되는데, 그건 미평가와 구분되지 않는다 — 모듈이 가장 조심해 온 것이
**「안 한 것」과 「해당 없는 것」의 혼동**이다.

**대신 공통 축 셋은 문구까지 똑같이 쓴다.** 부문이 갈려도 전사 요약에서 세 축은
나란히 비교된다(3절).

## 2. 대상과 수단

| 부문 | 대상(subject) — 무엇에 대해 | 수단(agent) — 무엇으로 |
|---|---|---|
| **설계 자동화** | **설계 업무** — 설계자가 손으로 하는 일 한 가지 | **자동화 수단** — 템플릿·스크립트·룰·생성 도구 |
| **검증 자동화** | **검증 항목** — 「이건 맞나」를 확인하는 규칙 한 가지 | **검증 수단** — 도구 내장 체커·사내 룰 엔진·자동 실행 벤치 |

연계(pair) = 대상 × 수단. 한 업무를 여러 수단이 나눠 맡을 수 있고(예: 도면
생성은 템플릿 + 사내 스크립트), 한 수단이 여러 업무에 걸린다 — 시뮬레이션 부문과
같은 모양이라 **엔진을 손대지 않는다.**

### 2-1. 대상 목록 초안 — 기구

| 설계 업무 | 검증 항목 |
|---|---|
| 부품 모델링(파라메트릭) | 간섭·클리어런스 |
| 조립 구조 설계 | 공차 누적 |
| 공차 배분 | 조립 가능성(공구 접근) |
| 도면 생성·치수 기입 | 체결·나사 규격 |
| 사출·금형 검토(구배·살두께) | 성형성 규칙(살두께·언더컷) |
| 방열 구조 설계 | 방열 설계 규칙 |
| 하네스·케이블 배치 | 굽힘 반경·간섭 |

### 2-2. 대상 목록 초안 — 회로

| 설계 업무 | 검증 항목 |
|---|---|
| 회로도 작성(블록·재사용) | ERC(전기 규칙) |
| 부품 선정·대체품 | 부품 정격·디레이팅 |
| 배치(placement) | DRC(설계 규칙) |
| 배선(routing) | 임피던스·SI 규칙 |
| 전원 설계 | PI(전원 무결성) 규칙 |
| BOM 생성 | BOM 정합(단종·미승인 부품) |
| 아트웍 출도 | 제조성(DFM)·테스트 포인트 |

⚠️ 이 목록은 **초안이자 전사 표준 사전**의 재료다. 사업부가 자기 이름으로
바꿔 쓰는 게 아니라, 표준 목록에서 **골라 세운다**(6절). 디지털 스레드의
「표준 구간 → 사업부의 구간」과 같은 구조다.

### 2-3. 기구·회로는 부문이 아니라 **대상의 속성**

부문을 넷(설계-기구·설계-회로·검증-기구·검증-회로)으로 쪼개지 않는다.

- 쪼개면 화면이 넷으로 늘고, **기구와 회로를 나란히 못 본다.** 「우리 회로는
  검증만 자동, 기구는 설계만 자동」이 이 모듈이 보여 줘야 할 그림인데 그게 끊긴다.
- 속성이면 필터·모판 묶음·요약 열로 언제든 갈라 볼 수 있다. 시뮬레이션의
  「제품군」·「모델 종류」와 같은 자리다.

⇒ `subject.domain` 한 칸을 더한다: `기구 · 회로 · SW·펌웨어 · 공통`.
   (마이그레이션 한 줄. 뒤에 올 부문도 같은 칸을 쓴다.)

## 3. 축 — 공통 셋 + 부문 고유

「축이 모자라 보인다」는 걱정의 답은 **축을 늘리는 것이 아니라 대상을 잘게 하는
것**이다(7절). 그 위에서 축은 이만큼이면 충분하다.

### 3-1. 공통 축 (두 부문 같은 문구 — 전사 요약에서 나란히 선다)

| 축 | 종류 | 칸 | 같이 적는 근거 | 대표 수치 |
|---|---|---|---|---|
| **자동화 수준** | 택1 | 수동 → 표준화 → 반자동 → 자동 → 자율 | 1건 소요 시간(Hr) | 「반자동」 이상 % |
| **적용 범위** | 택1 | 이슈 대응 → 대표 모델 → 신규 개발 전 모델 → 파생·지역 변형까지 | 대상 제품군 | 「신규 개발 전 모델」 이상 % |
| **효과** | **값**(%) | 미평가 → 30% 미만 → 30~70% → 70% 이상 (사업부별 문턱) | 전 소요(Hr) · 후 소요(Hr) · 연간 건수 | 평균 절감률 % |

**자동화 수준의 칸 뜻** — 부문마다 같은 자리에 다른 일이 온다. 문구를 이렇게
읽는다:

| 칸 | 설계 자동화 | 검증 자동화 |
|---|---|---|
| **수동** | 처음부터 끝까지 사람이 그린다 | 사람이 눈으로 본다 |
| **표준화** | 템플릿·표준 부품이 있고 가져다 쓴다 | 체크리스트가 있고 사람이 짚는다 |
| **반자동** | 도구가 만들고 사람이 손본다 | 도구가 걸러 내고 사람이 판정한다 |
| **자동** | 입력만 주면 나온다(사람은 승인) | 규칙이 스스로 판정한다(사람은 예외만) |
| **자율** | 조건을 바꿔가며 스스로 탐색·최적화 | 원인 후보·수정안까지 낸다 |

**효과 축이 값(%)인 이유** — 정확도 축과 같은 구조를 그대로 쓴다. 값을 적으면
칸이 문턱으로 정해지고, 기록이 줄줄이 쌓이며, 문턱은 사업부별 설정이다. 근거
칸에 「전 소요 · 후 소요 · 연간 건수」를 적게 하면 **연간 절감 시간이 저절로
셈된다** — 사업부가 가장 자주 묻는 숫자이고, 사람이 직접 적게 하면 서로 다른
기준으로 적힌다.

### 3-2. 설계 자동화 고유 축

| 축 | 종류 | 칸 | 근거 | 대표 수치 |
|---|---|---|---|---|
| **산출물 범위** | 묶음(겹쳐 켬) | 형상·회로도 · 도면·아트웍 · BOM·부품표 · 해석/검증 입력 · 제조 데이터(NC·거버) | 산출물 예시 | 항목별 채택률 띠 + 적용 단계 수(평균) |

한 번 돌렸을 때 **무엇까지 나오나**를 잰다. 「형상만 나오고 도면은 손으로」와
「도면·BOM까지」는 자동화 수준이 같아도 값어치가 다르다. 자동화 축(묶음)과
같은 화면 문법이라 요약·상세·모판이 그대로 돈다.

### 3-3. 검증 자동화 고유 축

| 축 | 종류 | 칸 | 근거 | 대표 수치 |
|---|---|---|---|---|
| **개입 시점** | 택1 | 설계 완료 후(사람이 돌림) → 단계 게이트에서 → 저장·커밋마다 → 위반이면 진행 차단 | 도는 자리(도구·CI) | 「저장·커밋마다」 이상 % |
| **검증 커버리지** | **값**(%) | 미평가 → 30% 미만 → 30~70% → 70% 이상 | 전체 규칙 수 · 자동 판정 규칙 수 | 평균 커버리지 % |

- **개입 시점**이 검증 자동화의 진짜 성숙도 신호다. 같은 룰 체크라도 출도 뒤에
  도는 것과 저장할 때마다 도는 것은 불량이 새는 양이 다르다. 「진행 차단」은
  게이트로 굳은 상태다.
- **커버리지**의 분모는 「그 항목이 가진 규칙 수」다. 셀 수 없는 항목이 있을 수
  있어 **「모름」을 허용**한다(디지털 스레드의 unknown_ok와 같은 장치).

### 3-4. 후보 — 지금은 넣지 않는다

| 후보 축 | 왜 미루나 |
|---|---|
| 판정 신뢰도(오검출로 사람이 재검토하는 비율) | 커버리지의 근거 칸으로 먼저 받아 본다. 따로 축이 되면 두 축이 같은 것을 두 번 묻는다 |
| 재사용 자산(라이브러리·템플릿·룰의 정비 수준) | 「자동화 수준 = 표준화」 칸이 이미 그 뜻이다. 겹친다 |
| 데이터 연결(도구 사이 입출력이 자동인가) | **디지털 스레드 부문이 재는 것.** 여기서 또 재면 두 부문이 어긋난 답을 낸다 |

## 4. 「자동화」라는 말이 세 곳에 있다 — 경계

| 어디 | 무엇의 자동화인가 | 대상 |
|---|---|---|
| 시뮬레이션 부문의 **자동화 축** | 해석 파이프라인(전처리→실행→후처리→보고) | 시험 × 시뮬레이션 |
| **설계 자동화 부문** | 설계 산출물이 나오는 과정 | 설계 업무 × 자동화 수단 |
| **검증 자동화 부문** | 규칙 판정이 도는 과정 | 검증 항목 × 검증 수단 |

같은 도구가 세 곳에 이름을 올릴 수 있다(예: 사내 스크립트). 재는 것이 다르므로
그래도 된다. 다만 **화면 문구에는 늘 대상을 붙여 부른다** — 「자동화」 홀로 쓰면
반드시 헷갈린다(PLAN.md 3-1의 같은 경고).

디지털 스레드와의 경계도 한 줄로: **스레드는 데이터가 조직·시스템을 건너는
자리(전달), 자동화 두 부문은 한 조직 안에서 일이 도는 방식(작업).**

## 5. 화면 — 새로 만들 것이 없다

| 화면 | 그대로 도나 | 손볼 곳 |
|---|---|---|
| 요약(전사) | ✅ 축 × 사업부 표 | 축마다 대표 수치 함수만 추가(3절 오른쪽 열) |
| 요약(사업부) | ✅ 축마다 판 + 앞선·취약 연계 | — |
| 상세 | ✅ 한 줄에 수단 하나, 켠 것 배지 | 열 이름(시험→설계 업무 / 검증 항목) |
| 변화 | ✅ 축마다 선 그래프 | — |
| 모판 | ✅ 담당 부서로 묶고 축 색 | **묶음을 「분야(기구·회로)」로도** 고를 수 있게 |
| 목록 | ✅ 대상 × 수단 표 | 「분야」 열 + 필터 |
| 연계 창 | ✅ 축별 사다리·근거·이력 | — |

새 부문이 화면을 새로 요구하면 **엔진 설계가 틀린 것**이다(PLAN.md 9절 H 판의
시험대). 지금 안으로는 요구하지 않는다 — 축 종류가 전부 이미 있는 넷
(택1 rung · 값 value · 묶음 set · 표 matrix 중 앞의 셋)이기 때문이다.

## 6. 채우기 — 표준 사전에서 골라 세운다

가장 큰 일은 축이 아니라 **대상 목록을 사업부가 채우는 것**이다. 자유 입력으로
두면 사업부마다 이름이 갈려 전사 비교가 깨진다(시스템 사전에서 겪은 일이다).

```
전사 표준 사전 (사무국)          사업부의 대상
설계 업무 20~30 · 검증 항목 20~30  →  고른 것만 세운다 + 필요하면 직접 추가
      분야(기구·회로)로 갈림             (직접 추가한 것은 사전 후보로 모인다)
```

디지털 스레드의 「표준 구간 → 구간」과 같은 구조라 **모델·화면·정돈(합치기)까지
재사용**한다. 사업부가 처음 열었을 때 빈 화면이 아니라 「고를 목록」을 보는 것이
채우기 시작의 문턱을 가장 크게 낮춘다.

## 7. 축이 모자라 보이는 문제의 답

| 지렛대 | 뜻 |
|---|---|
| **대상을 잘게** | 축 넷이어도 대상이 40개면 「어디는 되고 어디는 안 되는가」의 지도가 나온다. 시뮬레이션 부문이 시험 44개로 얻은 것이 그것이다 |
| **분야를 속성으로** | 한 표에서 기구·회로를 갈라 보면 축 하나가 두 배로 읽힌다 |
| **근거 칸을 셈의 재료로** | 「전 소요·후 소요·연간 건수」를 받으면 축을 늘리지 않고도 연간 절감 시간이 나온다 |
| **연간 건으로 쌓는 것** | 사다리로 못 재는 스팟성 활동은 「해석 활용 기록」처럼 건으로 쌓는다 — 자동화에도 그런 게 나오면 같은 자리를 쓴다 |
