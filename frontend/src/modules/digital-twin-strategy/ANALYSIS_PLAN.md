## 1. 계획서의 제안을 줄입니다

PLAN.md 는 ③ 에 **SWOT · 3C · VRIO** 세 렌즈를 두자고 했습니다. 세 개를 다
만들지 않습니다. 이유는 하나입니다 — **우리 데이터로 채울 수 있는 것이 절반뿐**
이라서입니다.

| | 포탈 데이터로 채워지나 |
|---|---|
| **S 강점** | **된다** — 진단의 높은 레벨, 사업부 간 격차의 상위 사업부 |
| **W 약점** | **된다** — 진단의 낮은 레벨, 발견 사항 |
| **O 기회** | 안 된다 |
| **T 위협** | 안 된다 |
| 3C · VRIO | 거의 다 백지 |

⚠️ **격자를 주면 채우는 것이 목적이 됩니다.** 이 모듈이 진단에서 세부 판단
격자를 맨 아래로 내리고 접어 둔 것과 같은 함정입니다. 렌즈를 셋으로 늘리면
백지가 세 배가 되고, 그러면 인상평이 세 배로 늘어납니다.

**SWOT 하나만, 절반은 자동으로 채웁니다.** 3C·VRIO 는 만들지 않습니다.
(PLAN.md 의 「[결정 필요] 1차는 각 단계 2개씩으로 줄이는 것도 방법」에 대한 답)

## 2. 근거 있는 절반과 없는 절반을 **선으로 가릅니다**

```
③ 분석
 ┌ 근거 있음 ──────────────────────────────┐
 │ S 강점    진단·발견 사항에서 후보 제시    │
 │ W 약점    진단·발견 사항에서 후보 제시    │
 └────────────────────────────────────────┘
 ┌ 근거 없음 ──────────────────────────────┐
 │ O 기회    ← 설문으로 물어봅니다           │
 │ T 위협    ← 설문으로 물어봅니다           │
 └────────────────────────────────────────┘
```

넷을 같은 무게로 보여주면 **O/T 가 인상평으로 채워집니다.** 화면이 "이 둘은
근거가 다르다"고 말해야 합니다. PLAN.md 5절의 「근거 없으면 근거 없음으로 눈에
띄게 표시」가 이 자리입니다.

## 3. 백지는 **설문으로 메웁니다**

O/T 는 포탈에 없는 정보입니다. 그렇다고 사무국 한 사람이 백지에 쓰면 그건
전략이 아니라 그 사람의 인상입니다.

**설문 모듈이 이미 그 일을 합니다.** 연결키만 넓히면 됩니다.

```
지금:  organization:readiness  …  진단의 조직 역량 5축
더함:  analysis:opportunity        기회
       analysis:threat             위협
```

「우리 사업부가 3년 안에 마주할 가장 큰 위협은?」은 **설문 문항입니다.**
서술형이면 AI 가 주제로 묶고(인용문 대조 포함), 객관식이면 쏠림과 갈림이
그대로 나옵니다. 익명성·감사 로그·표 입력이 전부 이미 있습니다.

⚠️ **이것이 '외부 환경'은 아닙니다.** 현장이 **인식하는** 기회와 위협입니다.
   그 한계를 화면에 적습니다 — 실제 시장·기술 동향과 같은 것으로 읽히면
   그게 더 위험합니다.

## 4. W 가 발견 사항과 겹치는 것은 정상입니다

「약점」과 「발견 사항」은 겹칩니다. 그래도 따로 두는 이유는 **쓰이는 곳이 다르기**
때문입니다.

    발견 사항 → 핵심 난제 → 이슈      올해 다룰 것을 고르는 길
    S·W·O·T  → TOWS(④)   → 솔루션    조합해서 솔루션을 만드는 재료

④ TOWS 는 S×O, W×O, S×T, W×T 네 조합에서 솔루션을 뽑습니다. 그러려면 네 칸이
다 있어야 합니다. 그래서 발견 사항을 **후보로 제시하되, 사람이 골라 요소로
승격**합니다 — 자동으로 옮기지 않습니다.

## 5. 데이터 모델

```
strategy_element
    plan_id
    kind          S | W | O | T
    title         한 줄
    detail        왜 그렇게 보는가
    division_id   특정 사업부면 지정, 전사면 비움
    source_type   assessment | finding | survey | manual
    source_ref    어디서 왔나 (후보의 key)
    order
```

`StrategyEvidence` 가 이미 `element` 를 대상 종류로 적어 두었습니다 —
설계 단계에서 자리를 비워 둔 것입니다.

⚠️ **status 를 두지 않습니다.** 이슈에는 `dropped` 가 있지만(판단의 기록),
   전략 요소는 "올해 안 함" 이라는 상태가 뜻이 없습니다. 아니면 지웁니다.

## 6. 순서

| 단계 | 내용 | |
|---|---|---|
| **1** | 모델 + 마이그레이션 + CRUD | **완료** |
| **2** | S/W 후보 도출 (진단·발견 사항에서) | **완료** |
| **3** | 화면 — 2×2, 근거 있음/없음을 선으로 가름, 흐름도 | **완료** |
| **4** | 설문 연결키 확장 (`analysis:*`) → O/T 후보 | **완료** |
| **5** | 사업부별 보기 (② 이슈와 공용) | **완료** |
| **6** | (다음) ④ TOWS + AX-5R 게이트 | |

**사업부별 보기**(5)는 계획에 없던 것을 더한 것입니다. 진단은 처음부터 사업부 ×
축 격자였는데 이슈·분석은 전사로 뭉쳐 있었습니다 — 데이터에는 `division_id` 가
있었는데 화면이 안 썼을 뿐입니다.

⚠️ **사업부를 골라도 전사 항목은 같이 보입니다.** MX 를 보는 사람에게 전사
이슈는 남의 것이 아닙니다. 대신 카드에 「전사」 표를 달아 그 항목이 MX 만의
것이 아님을 보입니다.

⚠️ 4단계까지 하고 나면 **설문 한 벌로 진단과 분석을 동시에 채울 수 있습니다.**
   조직 역량 문항과 기회·위협 문항을 한 설문에 넣으면 됩니다.

## 7. 위험

| 위험 | 대응 |
|---|---|
| SWOT 네 칸이 채우기 숙제가 된다 | 후보를 제시하고, 비어 있어도 진행을 막지 않는다 |
| O/T 가 인상평이 된다 | 근거 있는 절반과 선으로 가르고, 설문으로 메운다 |
| W 와 발견 사항이 중복으로 읽힌다 | 쓰이는 곳이 다름을 화면에 적는다(④ 의 재료) |
| 현장 인식을 외부 환경으로 오해한다 | 「응답자가 인식하는」 이라고 못 박는다 |
