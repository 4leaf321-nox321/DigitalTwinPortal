# 디지털 트윈 대시보드 — DX KPI 연결 반입 런북

작성 2026-08-01 · 대상: 운영 서버(오프라인) 작업자

---

## 이 문서를 쓰는 법

- **위에서부터 순서대로** 한다. 건너뛰지 않는다.
- 회색 상자의 명령을 **그대로 복사해** 실행한다.
- 각 단계 끝의 **확인**이 `[OK]` 면 다음으로, `[FAIL]` 이면 **멈추고** 그 단계의
  「막혔을 때」를 본다.
- **운영서버에는 AI 도 인터넷도 없다.** 판단이 필요한 지점은 전부 미리 적어 뒀다.
  여기 없는 상황을 만나면 **진행하지 말고** 개발 담당자에게 연락한다.
- 되돌리는 방법은 맨 아래 **R장**에 있다. 시작하기 전에 R장을 **먼저 한 번 읽는다.**

**소요 시간** 대략 25분 (백업 시간 제외).

**V2 컷오버(2026-07-31)보다 훨씬 가볍다.** 스위치를 켜지 않고, `.env` 도 고치지 않는다.
표를 **더하기만** 하므로 기존 데이터는 손대지 않는다.

---

## 무엇을 하는 작업인가

과제와 **DX KPI 지표**(가상 검증률·One Time Pass율 등, `DX 부문 KPI 관리` 모듈)를
연결하는 기능을 넣는다. 지금까지 두 모듈은 DB 수준에서 끊겨 있어서
**"이 KPI 를 밀고 있는 과제가 무엇인가"** 를 물을 방법이 없었다.

화면에 생기는 것은 둘이다.

| 어디 | 무엇 |
|---|---|
| 과제 편집창 ▸ 기본정보 탭 아래 | **DX KPI 연결** — 이 과제가 기여하는 지표를 고른다 |
| 대시보드 ▸ `결과 보고서` 오른쪽 | **KPI 연결** 탭 — KPI × 사업부 매트릭스 |

**기존 화면은 하나도 바뀌지 않는다.** 기존 데이터도 바뀌지 않는다.

> **사업부와 기능조직을 나눈다.**
> MX·VD·DA·NW·의료기기 는 KPI 를 직접 관리한다(목표·실적을 쌓는다).
> GTR·SR·CS 는 **기능조직**이라 자체 지표가 없고 위 사업부들을 지원한다.
> 그래서 기능조직 과제는 **어느 사업부의 지표를 미는지** 고르게 되어 있고,
> 그 기여는 매트릭스에서 **지원 대상 사업부 칸**에 잡힌다.
> 이 구분을 DB 가 어떻게 채웠는지 확인하는 것이 **6장이고, 이 작업의 유일한 판단 지점**이다.

## 6. ★ 운영 — 검증 (이 작업의 유일한 판단 지점)

```
python scripts\dt4_kpi_verify.py
```

**아무것도 고치지 않는 읽기 전용 스크립트다.** 몇 초면 끝난다.

**확인** — 마지막 줄이 이래야 한다. (`N` 은 7 또는 9 다 — 기존 연결이 없으면
확인할 항목이 둘 줄어든다. **`[FAIL]` 이 0 건인 것이 기준**이지 숫자가 아니다)

```
결과: [OK] N/N — 화면 확인으로 넘어가도 됩니다.
```

### 6-1. ★★ 5번 항목을 **눈으로** 본다

`[OK]` 가 다 떴어도 **5번 블록은 사람이 직접 읽어야 한다.**

```
5. ★ 사업부 / 기능조직 구분 — 여기가 이 검증의 핵심
        MX           KPI 보유
        VD           KPI 보유
        DA           KPI 보유
        NW           KPI 보유
        의료기기         KPI 보유
        GTR          기능조직
        SR           기능조직
        CS           기능조직
```

**기대값 — `GTR`·`SR`·`CS` 만 「기능조직」이고 나머지는 전부 「KPI 보유」다.**

> **왜 눈으로 봐야 하나**
> 이 값(`divisions.is_kpi_owner`)은 마이그레이션이 **운영 데이터를 보고** 채운다 —
> `kpi_records`/`kpi_targets` 에 한 번이라도 등장한 사업부만 KPI 보유로 본다.
> **아직 실적을 한 건도 안 올린 보유 사업부가 있으면 기능조직으로 잘못 잡히고,
> 그러면 매트릭스에서 그 사업부 열이 통째로 사라진다.**
> 스크립트는 이걸 `[FAIL]` 로 잡을 수 없다 — 실적이 없는 것과 기능조직인 것을
> 데이터만으로는 구분할 수 없기 때문이다. **판단은 사람이 한다.**

| 화면 | 어떻게 |
|---|---|
| 기대값과 **같다** | 7장으로 간다 |
| KPI 보유 사업부가 「기능조직」으로 잡혔다 | 아래 **6-2** 로 고친다 |
| 기능조직이 「KPI 보유」로 잡혔다 | 아래 **6-2** 로 고친다 |
| 모르는 사업부 이름이 있다 | **멈추고** 개발 담당자에게 연락 |

### 6-2. 구분이 다를 때만 — 한 줄로 고친다

**틀린 것만** 골라서 실행한다. `<사업부이름>` 은 위 화면에 나온 이름 그대로 쓴다.

```
psql -U postgres -d dxdigitaltwin -c "UPDATE divisions SET is_kpi_owner = true  WHERE name = '<사업부이름>';"
psql -U postgres -d dxdigitaltwin -c "UPDATE divisions SET is_kpi_owner = false WHERE name = '<사업부이름>';"
```

> ⚠️ 한글 사업부 이름(`의료기기`)이 `psql -c` 에서 깨지면, 아래처럼 **id 로** 고친다.
> 먼저 id 를 확인한다:
> ```
> psql -U postgres -d dxdigitaltwin -c "SELECT id, name, is_kpi_owner FROM divisions WHERE is_active;"
> ```
> 그다음:
> ```
> psql -U postgres -d dxdigitaltwin -c "UPDATE divisions SET is_kpi_owner = true WHERE id = <숫자>;"
> ```

고친 뒤 **6장을 다시 실행**해서 화면이 기대값과 같은지 확인한다.

### 6-3. 종이에 적어 둘 것

7번 블록의 숫자를 적어 둔다. 8장에서 화면과 맞춰본다.

```
7. 화면과 맞춰볼 숫자
  [정보] 활성 과제 NNN건 · DX KPI 지표 NN개 · 연결 N건
  [정보] 매트릭스 열이 될 사업부 N개: ...
  [정보] 기능조직 N개: ...
```

> **`DX KPI 지표 0개`** 로 나오면 → 아직 아무도 `DX 부문 KPI 관리` 화면을 연 적이
> 없다는 뜻이다. 그 화면을 한 번 열면 기본 15개가 자동으로 들어간다.
> 반입을 멈출 사유는 아니다. 8장에서 그 화면을 먼저 열어보면 된다.

## 8. 운영 — 화면 확인 (눈으로 본다)

다섯 가지를 순서대로 본다. **하나라도 다르면 R장으로 간다.**

### 8-1. 기존 화면이 그대로다

- 간트(`과제 진행 현황`)가 뜬다
- 대시보드 `전체 요약` 의 과제 수가 **6-3 에 적은 활성 과제 수**와 맞는다

> 여기까지 정상이면 **기존 기능은 안전하다.** 아래는 새 기능이다.

### 8-2. 과제 편집창 — 사업부 과제

아무 **MX·VD·DA·NW·의료기기** 과제를 연다. `기본정보` 탭 맨 아래.

- **DX KPI 연결** 영역이 보인다
- `대상: [사업부] 의 지표` 라고 표시된다 (고를 필요 없다)
- 지표가 `개발 / 제조 / 품질` 로 묶여 나온다
- 하나 체크 → **저장** → 창을 닫았다 다시 열면 **체크가 남아 있다**

> 저장 시 브라우저 콘솔(F12)에 `[DT] DX KPI 연결 저장 — N건` 이 찍힌다.

### 8-3. 과제 편집창 — 기능조직 과제

**GTR·SR·CS** 과제를 연다.

- **지원 대상 사업부** 칩이 나오고, 고르기 전에는 **지표가 잠겨 있다**
- 칩을 누르면 **즉시 켜지고** 지표가 활성화된다
- 두 사업부를 고르고 지표 하나를 체크 → 저장 → 다시 열면 유지된다

### 8-4. 매트릭스

`대시보드` → `결과 보고서` **오른쪽의 `KPI 연결`** 을 누른다.

- 열이 **KPI 보유 사업부 개수**만큼 있다 (6-3 에 적은 수)
- 기능조직은 열이 아니라 **표 아래 카드**로 나온다
- 8-3 에서 건 기능조직 과제가 **지원 대상 사업부 칸**에 `+1` 로 잡힌다
- `미연결 과제` 줄의 숫자를 누르면 과제 목록이 뜬다
- 지표 이름을 누르면 칸이 펼쳐지고 과제명이 나온다

### 8-5. 기존 KPI 화면

`DX 부문 KPI 관리` 모듈을 연다.

- `원시 데이터` · `요약` · `추이` 세 화면이 그대로 뜬다
- **KPI 항목 삭제**를 시도하면(연결이 걸린 지표) *"연결된 디지털 트윈 과제가 N건 있어
  삭제할 수 없습니다"* 가 뜬다 → **정상이다.** 연결을 먼저 풀어야 지울 수 있다

## R. 되돌리기 (롤백)

### R-0. 먼저 읽을 것

이번 작업은 **표와 칸을 더하기만** 한다. 기존 표는 건드리지 않는다.
그래서 **7장에서 서비스를 켜기 전까지는 되돌리기 비용이 거의 없다.**

되돌리기가 번거로워지는 유일한 경우는 **사용자가 이미 KPI 연결을 저장한 뒤**다.
그때 되돌리면 그 연결만 사라진다(다른 데이터는 안전하다).

### R-1. 서비스를 켜기 전 (8장 이전)

**폴더만 되돌리면 된다.** DB 는 그대로 둬도 문제없다 —
새 표(`dt2_project_kpi`)와 새 칸(`is_kpi_owner`)은 옛 코드가 **읽지도 쓰지도 않는다.**

```
ren <운영폴더> <운영폴더>_failed
ren <운영폴더>_before_20260801 <운영폴더>
net start <서비스이름>
```

**확인** — 기존 화면이 정상으로 뜬다. `KPI 연결` 탭은 없다(원래 상태다).

> DB 를 굳이 되돌릴 필요는 없지만, 원한다면 R-3 을 쓴다.

### R-2. 서비스를 켠 뒤 (사용자가 저장했을 수 있을 때)

1. 서비스를 내린다
2. R-1 대로 폴더를 되돌린다
3. **DB 는 그대로 둔다.** 저장된 KPI 연결은 옛 코드가 무시하므로 화면에 아무 영향이 없고,
   나중에 다시 반입하면 **그대로 살아난다**

**이 경우 DB 를 되돌리지 않는 것이 낫다.** 되돌리면 그 사이 저장된 연결이 사라진다.

### R-3. DB 까지 되돌려야 할 때

**한 줄이면 된다.** `downgrade` 의 인자는 "여기까지 내려간다" 는 **목적지**다
(되돌릴 리비전 번호가 아니다 — 자주 헷갈리는 지점이라 적어 둔다).

```
cd backend
flask db downgrade 860bcaf47aa8
```

**확인** — 아래 세 줄이 순서대로 지나간다.

```
Running downgrade c8f3a15e6b27 -> b7e2d90c4f15, add divisions.is_kpi_owner ...
Running downgrade b7e2d90c4f15 -> a1c48f70b2d3, add dt2_project_kpi.target_division ...
Running downgrade a1c48f70b2d3 -> 860bcaf47aa8, add dt2_project_kpi ...
```

> 개발 DB 에서 **왕복 시험을 마쳤다**(2026-08-01). 되돌린 뒤 과제·성과 건수가
> 그대로였고, 다시 올렸을 때 사업부 구분도 정확히 복원됐다.

> ⚠️ **`b7e2d90c4f15` 의 되돌리기는 데이터를 지운다.**
> 대상 사업부를 여럿 가진 연결(기능조직이 두 사업부를 지원하는 경우)은
> 좁은 유니크 제약을 다시 걸 수 없어 **가장 오래된 것 하나만 남기고 지운다.**
> 사용자가 이미 쓰기 시작했다면 R-2(그대로 두기)를 쓰는 편이 낫다.

전부 되돌린 뒤 확인:

```
psql -U postgres -d dxdigitaltwin -c "SELECT version_num FROM alembic_version;"
```

`860bcaf47aa8` 이 나오면 반입 전 상태다.

### R-4. 최후 — 백업에서 복원

위 어느 것으로도 안 되면 2장의 백업으로 되돌린다.

```
pg_restore -U postgres -d dxdigitaltwin -c dt_kpi_before_20260801.dump
```

**이건 반입 이후의 모든 변경을 잃는다.** 다른 방법을 먼저 시도한 뒤에 쓴다.

## 부록 — 자주 틀리는 것

| 증상 | 원인 | 어떻게 |
|---|---|---|
| 편집창에 DX KPI 영역이 안 보인다 | `dist` 가 옛 것이다 | 1-1 부터 다시 |
| 지표 목록이 비어 있다 | `kpi_definitions` 가 비었다 | `DX 부문 KPI 관리` 화면을 한 번 연다 |
| 저장 시 *"V2 쓰기가 켜져 있어야"* | `.env` 의 `DT2_WRITE_ENABLED` | 4-3 |
| 매트릭스 열이 8개다 | `is_kpi_owner` 가 전부 true | 6-2 로 GTR·SR·CS 를 false 로 |
| 매트릭스 열이 너무 적다 | 실적 없는 사업부가 기능조직으로 잡혔다 | 6-2 로 true 로 |
| 기능조직 과제에서 지표가 안 눌린다 | 지원 대상을 아직 안 골랐다 | **정상이다.** 칩을 먼저 고른다 |
| KPI 항목이 삭제되지 않는다 | 연결된 과제가 있다 | **정상이다.** 연결을 먼저 푼다 |
| 매트릭스 칸에 빗금이 있다 | 그 사업부가 관리하지 않는 지표다 | **정상이다.** 빈칸과 다르다 |
